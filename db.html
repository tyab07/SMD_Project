SECTION A — Short Answer Questions   [30 Marks]

Answer each question concisely. Each question carries 3 marks.

A1. A table Orders has 10 million rows. A query SELECT * FROM Orders WHERE CustomerID = 5042 takes 45 seconds without an index. Explain precisely why a B+ Tree index on CustomerID can reduce this to milliseconds. In your answer, discuss fan-out, tree height, and the number of disk I/Os involved in both cases.
A2. A DBA creates a composite index CREATE INDEX idx ON Sales(Region, Year, Revenue). For each of the following queries, state whether the index will be used (fully, partially, or not at all) and justify your answer:
  (i) WHERE Region = 'North'   (ii) WHERE Year = 2024   (iii) WHERE Region = 'North' AND Year = 2024   (iv) WHERE Revenue > 50000
A3. Explain why both of the following statements are true simultaneously: (i) "Indexes speed up SELECT queries," and (ii) "Too many indexes can slow down a database." What specific operations does an index negatively affect, and why? Also describe a scenario where a sequential scan is actually preferred over an indexed search.
A4. Consider this view definition:
CREATE VIEW HighEarners AS SELECT EmpID, Name, Salary, DeptID FROM Employee WHERE Salary > 80000;
(i) Is this view updatable? Justify with reference to the SQL updatability conditions.
(ii) If a user runs INSERT INTO HighEarners VALUES (99, 'Zara', 75000, 3), what happens and why?
(iii) How does WITH CHECK OPTION change the behavior?
A5. A materialized view MV_RegionSales computes SUM(Revenue) GROUP BY Region and was last refreshed at 8:00 AM. At 10:00 AM, a large batch of sales records is inserted. Explain: (i) what "staleness" means in this context; (ii) the difference between complete refresh and incremental (fast) refresh; and (iii) how the query optimizer can still exploit MV_RegionSales for a query asking for the total revenue per region (query rewriting).
A6. A view V is defined as: SELECT E.Name, D.DeptName, SUM(E.Salary) AS TotalSal FROM Employee E JOIN Department D ON E.DeptID = D.DeptID GROUP BY E.Name, D.DeptName. A junior developer attempts UPDATE V SET TotalSal = 90000 WHERE Name = 'Ali'. Identify every reason this update will fail, citing the exact SQL standard rules for non-updatable views.
A7. Describe a scenario where using a BEFORE trigger instead of an AFTER trigger leads to a logically incorrect outcome. Then describe a scenario where an AFTER trigger would fail to prevent bad data if mistakenly written as a BEFORE trigger. Use the Employee table context in both cases.
A8. User alice was granted UPDATE ON Employee WITH GRANT OPTION by the DBA. Alice then granted the same privilege to bob. Bob granted it to carol. The DBA now runs REVOKE UPDATE ON Employee FROM alice CASCADE. Trace the exact chain of revocations that occurs. What happens if the DBA uses RESTRICT instead of CASCADE?
A9. Two developers, dev1 and dev2, are assigned a role dev_role. Later, dev1 is found to have misused privileges. The DBA wants to revoke only dev1's access without affecting dev2 or the role itself, and without individual REVOKE statements for each privilege. Describe the correct approach using role management SQL (CREATE ROLE, GRANT, REVOKE), and explain why dropping the role would be wrong here.
A10. An SQL session begins when a user authenticates and ends when the connection is closed. (i) What role does the user-id play throughout the lifecycle of a session in terms of privilege checking? (ii) If a user's role is modified (ALTER ROLE) while their session is active, when do the changes take effect — immediately or at the next session? (iii) How does the DBMS use the session context to enforce object-level security (e.g., which tables a user may query)?
SECTION B — SQL / Query-Based Questions   [40 Marks]

Write complete, correctly-formatted SQL statements. Marks are allocated per sub-part.

Schema Reference

Use the following tables for all queries in this section:

Employee(EmpID, Name, Age, Salary, DeptID, City) Department(DeptID, DeptName, ManagerID) Project(ProjID, ProjName, Budget, City) Works_On(EmpID, ProjID, Hours)
B1. Indexes (10 Marks)
(a) Write a SQL statement to create a single-attribute index on the Name column of the Employee table. Name the index idx_emp_name.
(b) Create a composite (multi-attribute) index on Age and Salary columns of the Employee table. Name the index idx_age_salary. Explain in one sentence why the order of columns in a composite index matters.
(c) Consider the query below. Identify which index(es) from (a) and (b) would be used, and explain how the B+ Tree index helps process this range query efficiently.
SELECT Name, Salary FROM Employee WHERE Age > 25 AND Age < 28;
(d) Give two concrete reasons why creating an index on every attribute of a table is not recommended.
B2. Views (15 Marks)
(a) Create a view called DeveloperView that shows the EmpID, Name, Salary, and City of all employees working in the department named 'Development'.
(b) Create a view called SeattleView that shows all employees (Name, DeptName, Salary) located in 'Seattle'. This view requires a join between Employee and Department.
(c) Write a SQL query that retrieves all records from DeveloperView where the employee's Salary is greater than 60,000. Also write the equivalent rewritten query (i.e., the query that the DBMS would internally execute using the base table instead of the view).
(d) Consider the following attempt to insert a row into SeattleView:
INSERT INTO SeattleView VALUES ('Ali', 'HR', 55000);
Will this statement succeed? Explain why or why not, referencing the conditions for updatable views.
(e) A materialized view MV_DeptSalary stores pre-aggregated department salary totals. Write the SQL to create this materialized view. Then show how a query on department salary totals would be rewritten to use this materialized view for optimization.
B3. Triggers (15 Marks)
(a) Write a BEFORE INSERT row-level trigger called trg_min_salary on the Employee table. The trigger must enforce that no employee can be inserted with a Salary less than 30,000. If the salary is below the minimum, raise an appropriate application error / signal.
(b) Write an AFTER UPDATE row-level trigger called trg_salary_audit that fires whenever the Salary column of Employee is updated. It should insert a record into an AuditLog(EmpID, OldSalary, NewSalary, ChangeDate) table.
(c) Differentiate between BEFORE and AFTER triggers using the context of the Employee table. Give one practical use-case for each type.
(d) What is the difference between a row-level and a statement-level trigger? Provide an example scenario where a statement-level trigger would be more appropriate than a row-level trigger.
SECTION C — DCL: GRANT, REVOKE, Users & Roles   [20 Marks]
C1. GRANT Statement (8 Marks)
(a) Write SQL to grant the user alice the privileges SELECT and INSERT on the Employee table.
(b) Grant SELECT privilege on the Employee table to all users in the database. Which keyword do you use?
(c) Grant the user bob the ability to UPDATE only the Salary column of the Employee table, and also allow bob to pass this privilege on to other users. Write the complete SQL statement.
(d) What does GRANT ALL PRIVILEGES ON Employee TO charlie; do? List at least four privileges that would be covered by this statement.
C2. REVOKE Statement (6 Marks)
(a) Revoke INSERT privilege on the Employee table from the user alice.
(b) Write a single SQL statement to revoke SELECT and UPDATE privileges on the Department table from the users alice and bob simultaneously.
(c) Revoke ALL PRIVILEGES on the Project table from the user charlie. What happens to the privileges that charlie may have granted to other users? (Briefly explain the cascade effect.)
C3. Users & Roles (6 Marks)
(a) Write SQL to:
   (i) Create a new user dev_user with password 'Secure@123'.
   (ii) Grant dev_user the ability to connect to (create a session on) the database.
(b) Create a role called developer_role. Grant it SELECT, INSERT, and UPDATE privileges on the Employee table. Then assign this role to users dev_user and alice.
(c) Write the SQL to drop the role developer_role. What precaution should be taken before dropping a role?
SECTION D — Long Answer Questions   [20 Marks]

Attempt BOTH questions. Each question carries 10 marks.

D1. Comprehensive Scenario (10 Marks)
A university library management system has the following tables:
Member(MemberID, Name, Email, MemberType, City) Book(BookID, Title, Author, Price, Category) Loan(LoanID, MemberID, BookID, LoanDate, ReturnDate, Fine)
Answer all parts:

(a) Create an index idx_book_author on the Author column of the Book table. Then write a query that performs an exact-match lookup on Author = 'George Orwell' and explain how the index helps avoid a sequential scan.

(b) Create a view ActiveLoans that shows MemberID, Name, Title, LoanDate for all loans where ReturnDate IS NULL. Query this view to list all active loans from the city 'Islamabad'.

(c) Write a trigger trg_fine_calc that fires BEFORE INSERT on the Loan table. If the current date is more than 14 days after the LoanDate, it should automatically compute a fine of Rs. 10 per overdue day and store it in the Fine column.

(d) Design a full privilege management scheme for three user roles: Librarian (full access to all tables), Member (can only SELECT from Book and view their own Loan records via a view), and Admin (can CREATE and DROP tables, and grant privileges). Write the SQL for creating these roles and assigning appropriate privileges.
D2. Trigger, DCL & Role Design Scenario (10 Marks)
An online banking system has the following schema:
Customer(CustID, Name, Email, City, AccountType) Account(AccID, CustID, Balance, OpenDate, Status) Transaction(TxnID, AccID, TxnType, Amount, TxnDate, PerformedBy)
Answer all parts:

(a) Write an AFTER INSERT row-level trigger called trg_low_balance_alert on the Transaction table. After every debit transaction (TxnType = 'DEBIT'), check whether the account's remaining Balance falls below 1,000. If so, insert a warning record into an Alert(AccID, AlertMsg, AlertDate) table.

(b) Write a BEFORE UPDATE row-level trigger called trg_prevent_closed_txn on the Account table that prevents any update to Balance if the account's Status is 'CLOSED'. Raise a meaningful error message if the condition is violated.

(c) Design a complete DCL scheme for the following three roles:
  • Teller — can SELECT and INSERT into Transaction; can SELECT Account and Customer.
  • Manager — has all Teller privileges plus can UPDATE Account.Balance and UPDATE Account.Status; can grant Teller privileges to others.
  • Auditor — read-only SELECT on all three tables; cannot modify any data.
Write the full SQL: CREATE ROLE, GRANT privileges to roles, and assign roles to sample users u_teller1, u_manager1, and u_auditor1.

(d) The Auditor's role needs to be modified: add SELECT on a new table Alert without affecting any other privileges. Write the SQL using ALTER ROLE or an equivalent approach. Then explain what happens to currently active sessions of u_auditor1 — do the new privileges apply immediately or only after reconnecting? Justify your answer.
